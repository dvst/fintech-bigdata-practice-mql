Lección 12⏱ 20 min

Estrategia y documentación

Saber los operadores no basta: lo que convierte una consulta en un resultado fiable es cómo la planteas, la pruebas y la documentas. Esta lección es el método para hacerlo bien con este dataset.

  • Seguir un método repetible para cada consulta
  • Elegir la granularidad correcta antes de escribir código
  • Probar una consulta de forma convincente
  • Documentar con una plantilla clara
① Método

Seis pasos para cada consulta

PasoPreguntas que debes poder responder
1 · Leer¿Qué devuelve exactamente la consulta: una lista, un número, un ranking, varias listas? ¿Qué campos de salida? ¿Hay un «top N»? ¿Qué técnica encaja mejor (find, pipeline, MapReduce)?
2 · Explorar¿Qué campos intervienen? ¿Existen siempre? ¿Tienen siempre el mismo tipo? (Recetas de la lección 01.)
3 · Diseñar¿Qué representa cada documento en cada etapa (factura, visualización, película, cliente)? ¿Hay que desplegar arrays? ¿Agrupar? ¿Deduplicar?
4 · ConstruirUna etapa cada vez, mirando la salida con $limit; contando documentos entre etapas.
5 · Probar¿Da lo mismo por otro camino? ¿Cuadra con un documento revisado a mano? ¿Qué pasa con los casos límite?
6 · DocumentarPlantilla de abajo.
② Granularidad

La pregunta que evita la mitad de los errores

«¿Qué es una fila?» cambia a lo largo del pipeline. En este dataset hay varias respuestas posibles:

EntidadCómo se obtieneTrampa habitual
Facturala collection tal cualcontar facturas no es contar clientes (hay una por mes)
Visualización$unwind de Movies o Serieslas facturas sin el array desaparecen
Película (catálogo)$unwind + $group por títulosin deduplicar, las medias se ponderan por visualizaciones
③ Probar

Cómo demostrar que una consulta está bien

  • Comprobación cruzada: el mismo número calculado por dos caminos (countDocuments frente a $count; MapReduce frente a pipeline).
  • Verificación manual: elige un _id del resultado, ábrelo con findOne y comprueba a mano que cumple las condiciones.
  • Contraejemplos: busca documentos que no deberían salir y confirma que no salen.
  • Recuentos por etapa: { $count: "n" } tras cada etapa clave; anota las cifras.
  • Casos límite: documentos sin el campo, arrays vacíos, empates en el ranking, valores 0.
Rendimiento

Si quieres comentar la eficiencia: db.coleccion.find(…).explain("executionStats") o db.coleccion.explain("executionStats").aggregate([…]) muestran cuántos documentos se examinaron y si se usó algún índice.

④ Documentar

Plantilla para documentar una consulta

markdown
### Consulta · <título>

**Planteamiento**
- Qué se pide, con mis palabras: …
- Granularidad: cada documento del resultado representa … (factura / visualización / película …)
- Campos usados y anomalías encontradas (ausentes, tipos distintos, duplicados): …
- Decisiones y supuestos (empates, valores ausentes…): …
- Estrategia (etapas o fases y para qué sirve cada una): …
- Alternativa(s) consideradas y por qué elegí esta: …

**Consulta**
```js
db.coleccion.aggregate([
  // 1) … qué hace esta etapa
  { $match: { … } },
  // 2) …
])
```

**Verificación**
- Resultado (o sus primeras filas) y recuentos: …
- Comprobación cruzada (otro método que da lo mismo): …
- Verificación manual sobre un documento concreto (_id …): …
- Casos límite comprobados (documentos sin el campo, empates…): …
