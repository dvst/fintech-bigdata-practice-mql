Expresiones regulares

Cuando la condición no es «igual a» sino «tiene esta forma» (empieza por, termina en, contiene, sigue un formato) necesitas expresiones regulares. Es una de las herramientas más útiles para validar datos.

  • Usar $regex y los literales /…/ en find()
  • Anclar patrones con ^ y $
  • Describir formatos con clases y cuantificadores
  • Validar datos contando lo que cumple y lo que no
① Concepto

Un patrón describe una forma

Pruébalo con valores de ejemplo inventados (algunos incumplen el formato a propósito, para que veas fallos). Edita el patrón o pulsa los ejemplos:

El probador usa el motor de JavaScript; MongoDB usa PCRE. Para todo lo de esta lección se comportan igual.

② Sintaxis

Dos formas de escribirlo en MongoDB

mongosh
// 1) literal de JavaScript (lo más cómodo en mongosh)
db.__COL__.find({ "Movies.Title": /^Star Wars/ })
db.__COL__.find({ "Movies.Title": /star wars/i })          // i = sin distinguir mayúsculas

// 2) operador $regex con un string
db.__COL__.find({ "Movies.Title": { $regex: "^Star Wars" } })
db.__COL__.find({ "Movies.Title": { $regex: "star wars", $options: "i" } })
La doble barra invertida

Dentro de un string la barra invertida se escapa: { $regex: "\\d$" }. Si escribes "\d$", JavaScript convierte \d en una simple d y buscas textos que terminan en la letra d. En los literales /\d$/ no hay que duplicarla.

④ Detalles

Lo que conviene saber

  • Sobre arrays, el patrón se prueba contra cada elemento: { "Movies.Details.Genres": /^Sci/ }.
  • Solo funciona con strings. Un campo numérico (como Client.Phone) nunca coincide con una regex. Para eso hay que convertirlo a texto en agregación ($toString + $regexMatch, lección 09).
  • Negar: { campo: { $not: /patrón/ } }. Igual que $ne, también coincide cuando el campo no existe: añade $exists: true si no lo quieres.
  • Varios patrones: { campo: { $in: [/^The /, /^A /] } }.
  • Rendimiento: un patrón anclado con ^ y sin i puede usar un índice; /abc/i obliga a revisar todos los valores.
⑤ Validar

Método para validar un formato

  1. Descríbelo con palabras: «dos dígitos, barra, ocho dígitos, barra, dos dígitos y una T».
  2. Tradúcelo a un patrón anclado de principio a fin (^…$): sin anclas validas solo un trozo.
  3. Cuenta los que cumplen y los que no (con $not): ¿suman el total?
  4. Mira ejemplos de los que no cumplen con .limit(5): ¿son errores de datos o tu patrón es demasiado estricto?
  5. Piensa en casos límite: espacios, caracteres repetidos, partes vacías, mayúsculas.
Documenta tus pruebas

Una consulta con regex queda muy bien probada si muestras ejemplos que deben coincidir, ejemplos que no deben coincidir y los recuentos del paso 3.
