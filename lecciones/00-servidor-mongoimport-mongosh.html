Servidor, mongoimport y mongosh

Antes de escribir una sola consulta necesitas tres piezas: el servidor que guarda los datos, el importador que los carga y el cliente desde el que preguntas. Aquí ves cómo encajan y lo compruebas contra tu propia instalación.

  • Distinguir mongod, mongosh y mongoimport
  • Entender la jerarquía server → database → collection → document
  • Importar un fichero JSON con mongoimport
  • Moverte por la shell: use, show, find().limit()
① Concepto

Tres programas, un flujo

ProgramaQué esCuándo lo usas
mongodEl servidor (daemon). Guarda los datos en disco y atiende peticiones en el puerto 27017.Debe estar arrancado siempre: es el «servidor» o «listener».
mongoimportHerramienta de línea de comandos (MongoDB Database Tools). Lee JSON/CSV/TSV e inserta documentos.Una vez, para cargar el fichero de datos. Se ejecuta en la terminal del sistema, no dentro de mongosh.
mongoshEl cliente interactivo (MongoDB Shell). Un intérprete de JavaScript conectado al servidor.Para todas las consultas: find(), aggregate(), mapReduce().
② Jerarquía

Server → database → collection → document

Un servidor contiene varias databases; cada una contiene collections; cada collection contiene documents (objetos tipo JSON, guardados internamente como BSON). Si vienes de SQL, esta tabla te orienta, aunque la analogía no es perfecta:

SQLMongoDBDiferencia clave
databasedatabaseIgual.
tablecollectionNo tiene esquema fijo: cada documento puede tener campos distintos.
rowdocumentPuede contener subdocumentos y arrays (p. ej. Movies es un array de películas).
columnfieldSe accede a lo anidado con notación de puntos: "Client.Name".
JOINdatos embebidos (o $lookup)En este dataset todo lo de una factura está dentro del mismo documento.
Una factura = un documento

En tu dataset cada documento es la factura mensual de un cliente: datos del cliente, contrato, y lo que vio ese mes (Movies, Series). Hay 12 meses de 2025, así que un mismo cliente aparece en varios documentos.

③ Importar

mongoimport

Se ejecuta en la terminal de tu sistema (zsh/bash), con mongod ya en marcha. Forma general:

bash
mongoimport --db <database> --collection <collection> --file <fichero.json>
OpciónSignificado
--db / -dBase de datos destino. Se crea sola al insertar el primer documento.
--collection / -cCollection destino. Si la omites, usa el nombre del fichero sin extensión (facturas.json → facturas).
--fileRuta al fichero. Si tiene espacios, entre comillas.
--dropBorra la collection antes de importar. Útil si quieres empezar de cero.
--jsonArraySolo si el fichero es un único array [ {...}, {...} ]. Un fichero con objetos uno tras otro (lo más habitual en volcados) no lo necesita.
--uriCadena de conexión si el servidor no está en localhost:27017.
Líneas ≠ documentos

Un volcado JSON «bonito» (pretty-printed) puede tener millones de líneas aunque contenga muchos menos documentos, porque cada documento ocupa decenas de líneas. Lo que importa es cuántos documentos hay, y eso lo cuenta MongoDB: lo verás en el laboratorio.

Comprueba siempre la carga

Fíjate en la línea final que imprime mongoimport (N document(s) imported successfully. 0 document(s) failed to import.) y compárala con lo que esperabas: es la prueba de que la carga fue completa.

④ La shell

Primeros pasos en mongosh

Al abrir mongosh sin argumentos te conectas a mongodb://127.0.0.1:27017 y a la database test. La variable db apunta siempre a la database actual.

mongosh
show dbs                      // databases del servidor
use __DB__                   // cambia la database actual (db)
show collections              // collections de esa database
db.__COL__.countDocuments()       // cuántos documentos hay
db.__COL__.findOne()              // un documento cualquiera
db.__COL__.find().limit(3).pretty()  // los 3 primeros
¿Y .pretty()?

Verás .pretty() en muchos tutoriales porque en la shell antigua (mongo) la salida salía en una sola línea. En mongosh la salida ya viene formateada; .pretty() se sigue aceptando y no hace daño.

Cursores y «it»

find() no devuelve un array, sino un cursor: mongosh te enseña los primeros 20 documentos y escribe Type "it" for more. Escribe it para ver los siguientes 20.
