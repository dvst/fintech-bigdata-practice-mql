Lección 06⏱ 30 min

Aggregation pipeline

El aggregation pipeline es una cadena de etapas por la que pasan los documentos: cada una los filtra, los transforma, los agrupa o los ordena, y entrega el resultado a la siguiente.

  • Entender el modelo de etapas y por qué su orden importa
  • Traducir find() a $match, $project, $sort, $limit
  • Crear, renombrar y calcular campos con "$campo"
  • Construir y depurar un pipeline etapa a etapa

② De find() a aggregate()

Lo que ya sabes, en forma de etapas

find()aggregate()
find({ filtro }){ $match: { filtro } } (mismos operadores: lecciones 02–05)
find({}, { a: 1, _id: 0 }){ $project: { a: 1, _id: 0 } }
.sort({ a: -1 }){ $sort: { a: -1 } }
.skip(10) · .limit(5){ $skip: 10 } · { $limit: 5 }
countDocuments(filtro){ $match: … }, { $count: "nombre" }
— (imposible con find)$group, $unwind, $facet, campos calculados…
El orden de las etapas importa

En find() el servidor siempre ordena antes de limitar. En un pipeline, cada etapa se aplica en el orden en que la escribes: [{ $limit: 5 }, { $sort: { TOTAL: -1 } }] toma 5 documentos cualesquiera y luego los ordena. Casi nunca es lo que quieres.

③ Dar forma

$project, $addFields y la sintaxis "$campo"

mongosh
db.__COL__.aggregate([
  { $match: { "contract.country": "Spain", billing: "March 2025" } },
  { $project: {
      _id: 0,
      cliente: "$Client.Name",                    // renombrar / aplanar
      tarifa: "$contract.product.Reference",
      importe: "$TOTAL",
      iva: { $round: [ { $multiply: ["$TOTAL", 0.21] }, 2 ] },   // calcular
      moneda: { $literal: "EUR" }                 // valor fijo
  } }
])
EtapaQué hace
$projectDefine la forma completa de salida: solo quedan los campos que nombres (más _id si no lo quitas).
$addFields / $setAñade o sustituye campos y conserva todos los demás.
$unsetQuita campos: { $unset: ["Movies", "Series"] }.
$replaceRoot / $replaceWithConvierte un subdocumento en el documento entero.
"$campo" frente a "campo"

A la derecha de los dos puntos, "$TOTAL" es el valor del campo y "TOTAL" es el texto «TOTAL». A la izquierda (nombres de campo de salida o claves de $match) nunca se pone $.

④ Construir y depurar

Método de trabajo

  1. Empieza por $match: reduce cuanto antes los documentos (y puede usar índices).
  2. Añade una etapa cada vez y mira la salida antes de seguir.
  3. Mientras desarrollas, pon { $limit: 3 } detrás de la etapa que estás probando, o trabaja con { $match: { _id: "…" } } sobre un documento que conozcas.
  4. Guarda el pipeline en una variable y añádele etapas: var p = [ … ]; db.__COL__.aggregate(p).
  5. Cuenta documentos entre etapas con { $count: "n" } para detectar pérdidas inesperadas.
mongosh
var p = [
  { $match: { "contract.country": "Spain" } },
  { $project: { _id: 0, importe: "$TOTAL", mes: "$billing" } }
]
db.__COL__.aggregate(p.concat([{ $limit: 3 }]))   // probar con 3
db.__COL__.aggregate(p.concat([{ $count: "n" }]))  // ¿cuántos quedan?
Límites

Cada etapa puede usar hasta 100 MB de memoria; si una agrupación u ordenación grande lo supera, pasa { allowDiskUse: true } como segundo argumento de aggregate() (en MongoDB 6.0+ ya es el comportamiento por defecto).
