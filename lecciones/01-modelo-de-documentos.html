Modelo de documentos

Un documento de MongoDB no es una fila: es un árbol. Aquí aprendes a leerlo, a nombrar cualquier rama con notación de puntos y a descubrir que no todas las facturas tienen la misma forma, la trampa número uno de este dataset.

  • Leer un documento con subdocumentos y arrays
  • Escribir la ruta de cualquier campo con notación de puntos
  • Reconocer los tipos BSON del dataset
  • Detectar campos ausentes y tipos que cambian entre documentos
① Concepto

Un documento es un árbol

Este es un documento inventado con la misma estructura que las facturas del dataset. Pulsa cualquier campo: verás la ruta con la que se consulta, su tipo y un ejemplo de find().

Despliega Movies → un elemento → Details → Cast → Stars: hay arrays dentro de subdocumentos dentro de arrays.

Tres tipos de «caja»

EstructuraEn el datasetCómo se alcanza
Valor simple"TOTAL": 16.65, "billing": "January 2025"Por su nombre: "TOTAL"
Subdocumento (object)Client, contract, contract.productUniendo nombres con puntos: "contract.product.type"
ArrayMovies, Series, Genres, StarsIgual que un subdocumento: "Movies.Title" mira el Title de todos los elementos
La regla de las comillas

Una ruta con puntos siempre va entre comillas: { "Client.Name": "Elena" }. Y en este dataset muchos campos tienen espacios ("Viewing PCT", "monthly fee", "customer code"), así que las comillas son obligatorias también por eso.

② Tipos

Tipos BSON que vas a encontrar

MongoDB guarda los documentos en BSON (JSON binario con más tipos). Lo que importa para consultar:

Tipo BSONEjemplo en el datasetOjo con…
string"Title": "The Paper Moon"Las comparaciones son alfabéticas y distinguen mayúsculas.
int / long / double"Phone": 555010001, "TOTAL": 16.65Todos son «números»: $gt compara bien entre ellos. Algunos TOTAL son int (p. ej. 605) y otros double.
object"Client": { … }Un subdocumento. Se entra con .
array"Genres": ["Action", "Horror"]Las condiciones se aplican a cada elemento (lección 04).
missingFacturas sin MoviesNo es un tipo: el campo no existe. No es lo mismo que null.
Las fechas son texto

"Date": "15/01/2016" o "start date": "27/11/14" son strings, no fechas BSON. Si las comparas con $gt se comparan como texto, carácter a carácter: "15/01/2016" > "01/02/2016" es verdadero aunque enero vaya antes que febrero. Para operar con fechas de verdad hay que convertirlas (lo verás en agregación).

③ Esquema flexible

No todas las facturas tienen la misma forma

Una collection no impone esquema: cada documento lleva los campos que tenga. En este dataset pasa, por ejemplo, que:

  • muchas facturas no tienen Movies o Series (ese mes el cliente no vio nada de eso);
  • algunos clientes no tienen Phone, y algunos contratos no tienen end date;
  • dentro de Movies, a algunas películas les falta License, Budget o Gross;
  • un mismo campo puede tener tipos distintos en documentos distintos. Por eso conviene inventariar tipos antes de consultar.

Esta receta (es agregación, la entenderás en la lección 07; de momento cópiala) cuenta cuántos documentos tienen cada tipo en un campo:

mongosh
db.__COL__.aggregate([
  { $group: { _id: { $type: "$Client.Phone" }, n: { $sum: 1 } } }
])
text
[ { _id: 'missing', n: 5426 }, { _id: 'int', n: 48719 } ]
Por qué importa

Una consulta que funciona con los 3 primeros documentos puede fallar o dar resultados incompletos con el resto. Antes de escribir una consulta, inventaría los campos que vas a usar: ¿existen siempre?, ¿tienen siempre el mismo tipo? Y deja escrito lo que hayas encontrado.
